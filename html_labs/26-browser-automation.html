Why this matters

Browser automation adds a powerful external-action surface. The first exercise should be bounded, read-only, synthetic, and based on Microsoft's official hosted sample.

Learning objectives

  • Initialize the official Browser Automation sample
  • Provision its required workspace and identity roles
  • Read a synthetic flight-status page without performing writes

Core concepts

ConceptWhat it means in this lab
Browser sessionProvides an isolated automation environment.
ToolboxMakes the hosted browser tool available to the agent.
Action boundaryLimits the first task to read-only navigation and extraction.

Start here: end-to-end readiness

Use the project root. Run every command from microsoft-agent-framework-demos unless the lab explicitly changes folders. Commands use PowerShell on Windows.

Step 1 — Verify prerequisites

PowerShell
python --version
az --version

Step 2 — Create and activate the virtual environment

Create one course environment in the repository root. Reuse it for later labs.

PowerShell
python -m venv venv
.\venv\Scripts\Activate.ps1

If PowerShell blocks activation, allow scripts only for the current process and activate again:

PowerShell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1

Step 3 — Install the libraries

The repository requirements are pinned so every lab uses the same tested SDK surface.

PowerShell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check
Running only this lab outside the course repository

Install these direct packages:

PowerShell
python -m pip install agent-framework-core==1.15.0 agent-framework-foundry==1.11.0 azure-identity==1.25.3 python-dotenv==1.2.3 agent-framework-foundry-hosting==1.0.0b260827

Step 4 — Create the environment file

Create .env once from the safe template, then replace placeholders. Never commit .env.

PowerShell
Copy-Item .env.example .env
notepad .env
Environment
FOUNDRY_PROJECT_ENDPOINT=https://<foundry-resource>.services.ai.azure.com/api/projects/<project>
FOUNDRY_MODEL=<deployed-model-name>

Step 5 — Authenticate for classroom development

Sign in with the identity that has access to the Foundry project and any additional Azure resources.

PowerShell
az login
az account show --query "{subscription:name, tenant:tenantId}" -o table

Create or verify required resources

  1. In Microsoft Foundry, create or select a project, deploy the instructor-approved chat model, and copy its project endpoint and deployment name into .env.
  2. Grant the learner the project-level role required to invoke the deployment. For a shared class, provision this before the lab.
  3. Install azd and Docker, and obtain Owner or Contributor access to the target resource group.
  4. Create or provision the Playwright Workspace and Toolbox exactly through the official quickstart.
  5. Keep authentication, payments, bookings, and personal data out of the first browser lab.
  6. Browser Automation is preview and can incur Azure charges.

Initialize the current official Agent Framework sample

PowerShell
$env:AZURE_DEV_USER_AGENT='microsoft_foundry_course'
azd ai agent init -m "https://github.com/microsoft-foundry/foundry-samples/blob/main/samples/python/hosted-agents/agent-framework/responses/14-browser-automation-agent/azure.yaml" --deploy-mode container
Cost and cleanup: Azure Search, models, hosted agents, storage, browser workspaces, and optimization jobs can incur charges. Use instructor-provided resources where possible and follow your organization's cleanup policy after class.

Run and validate

Run the completed files

PowerShell
# Serve the synthetic page locally for inspection
python -m http.server 8000 --directory .\26_browser_automation\training_site
# For the Hosted agent, publish the page to an instructor-controlled HTTPS site and use the prompt in student_demo_prompt.txt

Expected result

  • The agent identifies the cancelled flight, route, and documented next action.
  • No form is submitted, no booking is changed, and no external link is followed.
Completion checkpoint: Do not mark the lab complete until the observed output matches these conditions.

Five-minute challenge

Add one delayed flight to the synthetic page and ask the agent to distinguish delayed from cancelled status without taking action.
